# deafmode language specification
version: 0.1
status: active

---

# purpose

the deafmode language system exists to:

- preserve operational clarity
- compress signal
- reduce emotional noise
- communicate inferred state
- maintain semantic consistency across artifacts, telemetry, and interfaces

the language should feel:

- restrained
- observational
- inferential
- durable
- ambient
- quietly intelligent

never theatrical.

---

# core philosophy

deafmode does not optimize productivity.

it protects operational stability.

the system exists to:
- detect drift
- preserve coherence
- reduce fragmentation
- maintain recovery margin
- surface environmental pressure

the language should reflect this.

---

# tone rules

## preferred qualities

- concise
- calm
- direct
- sparse
- operational
- low-emotion
- inference-heavy

## forbidden qualities

- motivational
- exaggerated
- alarmist
- gamified
- corporate
- pseudo-military
- biohacker jargon
- startup-speak

---

# formatting rules

## lowercase by default

use lowercase unless:
- denoting system states
- rendering section headers
- indicating classifications

example:

```txt
focus fragmentation increasing
```

---

## short declarative statements

good:

```txt
recovery margin narrowing
```

bad:

```txt
i think i may be getting burned out lately
```

---

## avoid conversational phrasing

bad:

```txt
looks like you had a rough night
```

good:

```txt
sleep consistency degraded
```

---

## avoid emotional interpretation

bad:

```txt
morale collapsing
```

good:

```txt
execution consistency weakening
```

---

# canonical sections

| section | meaning |
| SIGNAL | overall operational state |
| BODY | physiological condition |
| THOUGHT | cognition and mental load |
| TIME | scheduling and pressure |
| ENVIRONMENT | noise and external conditions |
| DRIFT | emerging instability |
| INFERENCE | interpreted state |
| RESPONSE | recommended correction |

# state transition model

```txt
STABLE
→ FRAGMENTING
→ DEGRADED
→ OVERLOADED
→ RECOVERING
→ STABLE
```

transitions should feel gradual.

avoid sudden catastrophic language.

# numerical philosophy

numbers are secondary.

prioritize:
- direction
- trend
- inference
- condition

good:

```txt
context switching increasing
```

acceptable:

```txt
sleep consistency: 72%
```

bad:

```txt
sleep score: 72
```

avoid metric obsession.

---

# inference style

the system should infer more than it displays.

examples:

```txt
attention environment porous
```

```txt
recovery capacity narrowing
```

```txt
deep work continuity weakening
```

```txt
stimulation load elevated
```

```txt
operational stability holding under load
```

---

# response style

responses should:
- remain calm
- remain brief
- avoid command tone
- avoid emotional urgency

good:

```txt
reduce evening stimulation
```

```txt
protect uninterrupted blocks
```

```txt
stabilize sleep timing
```

bad:

```txt
fix your sleep immediately
```

---

# dashboard behavior

the dashboard should:
- observe quietly
- surface drift gradually
- avoid notification spam
- avoid excessive animation
- feel infrastructural

the system should never:
- beg for attention
- gamify interaction
- pressure engagement
